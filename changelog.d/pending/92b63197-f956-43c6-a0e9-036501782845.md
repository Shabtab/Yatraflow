### Fixed

- **A trip page load now sends one Google Routes request, not sixteen.** One signed-in load sent two whole-route requests, then fourteen more, one for each leg. In development, React replayed the workspace effect. Nothing shared a request that was still in flight, so the same route was requested twice. Then the first request failed in transport. The app asked Google for every leg, and that could not work. Now two callers that ask for the same route, or the same leg, wait on one request. A caller that cancels no longer cancels the other caller. A failure that splitting cannot fix makes one OpenStreetMap route request, then falls back to estimates. Examples are a rejected fetch, an auth or quota refusal (401, 403, 429), and a quota guard refusal. Per-leg Google requests remain only for an answer with the wrong shape, such as a wrong leg count. The cancel signal of the page now reaches the Google request. A route with two stops now uses the single route answer from Google. The last part of a long route can have two stops, and it now does the same.
